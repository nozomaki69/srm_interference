# PER の値域チェック（Seed 別）

`script/check_per_range.py` の設計と、出力から何を決めるかの記録。

目的は一つだけ ――
**クリップ前の生 PER が値域 `[0, 1]` を外れる現象が、特定の Seed に集中しているのか、
全 Seed に均等に散っているのかを決める。**

前者なら外れ Seed を除外すれば済む。後者なら PER の定義そのものに由来する構造的な
問題で、Seed を落としても直らない。この分岐で次にやることが変わる。

---

## 1. 何を「範囲外」と呼ぶか

PER の定義は `script/analyze_csv.py::_one_side_per()`（:356-382）。

```
PER = 1 − n_rx / (macTxSuccessCount + macRetryCount + macMultipleRetryCount + macTxFailCount)
```

`n_rx` は受信側が実際に受信したデータフレーム数、分母は送信側の MAC 再送カウンタ 4 種の
和。定義の詳細と列の対応は `docs/per_measurement.md` §1–§2 を参照。

実装は結果を `[0, 1]` にクリップしている（:379-382）。このドキュメントで「生 PER」と
呼ぶのは、**クリップを掛ける前の `1 − n_rx/分母`** のこと。

### PER > 1 は構造的に起こり得ない

`n_rx ≥ 0` かつ分母 `> 0` なので `n_rx/分母 ≥ 0`、したがって `1 − n_rx/分母 ≤ 1` が
常に成り立つ。`PER > 1` になるには `n_rx < 0` が必要で、これは受信数の定義上あり得ない。

それでも実測で数えるのは、**PER の性質を確かめるためではなくデータの健全性を
確かめるため**である。`PER > 1` が 1 件でも出たら、それは PER の問題ではなく

- CSV の列がずれている（ヘッダと行の対応が壊れている）
- カウンタが負の値を持っている
- `create_csv.py` の集計が壊れている

のいずれかを意味する。先に潰すべき別の問題として検出したい。スクリプトは
`n_rx < 0` / `分母 < 0` も `n_invalid` として別建てで数える。

### PER < 0 は実際に起きている

実データで **クリップ率 9.50%（342,042 / 3,599,932）** が観測済み。`n_rx > 分母` に
なるケースで、約 10 回に 1 回。機序の候補は `docs/per_measurement.md` の付録に
まとめてあるので、ここでは繰り返さない。要点だけ再掲すると:

- 分母から `macCsmaFailCount` を外しているため、**一度は電波に出て受信側に届いたのに
  分母に入らないフレーム**が存在する（`driot_mac.cpp:841` の `ProcessCcaFailure` が
  `retryTxCount++` を進めないままフレームを捨てる）。定常なら
  `PER = 1 − (1 − PER_frame)/(1 − p_csma)` となり、`PER_frame < p_csma` のとき負。
- td ではさらに、分子 `Rx(W4)` と分母 `S(W0)+R(W1)+M(W2)+F(W3)` が**互いに素な
  フレーム集合**なので、`n_rx ≤ 分母` という包含関係に構造的な根拠が無い。

原因の切り分け（負荷別・RSSI ビン別・方向別・分母に csma を足した場合）は
`script/diagnose_per_clip.py` が既にやっている。**このスクリプトはそれとは別の軸、
Seed 別だけを見る。**

### 分母 0 も併記する

`_one_side_per()` は分母が 0 以下のとき `0.0` を返す（:374-375）。これは
「完全に届いた（PER = 0）」と区別がつかないまま下流の統計量に入る。範囲外では
ないが同種の汚染なので、`n_zero_denom` として数えて表に併記する。

---

## 2. なぜ Seed 別に見るのか

Seed は 0–99 の 100 本（`interference_2pan_config.py:103` の `SIMULATION_SEEDS`）。
Seed ごとにノード配置とシャドウイングの実現値が変わるので、「たまたま配置が極端な
Seed」が範囲外を量産している可能性がある。

| 観測 | 結論 | 次にやること |
|---|---|---|
| 特定の少数 Seed に集中 | その Seed の配置が外れ値 | 該当 Seed を除外して再解析 |
| 全 Seed にほぼ均等 | PER 定義に由来する構造的な問題 | 除外では直らない。分母の定義（csma を含めるか）を変えるか、PER の定義自体を見直す |
| `n_invalid > 0` | CSV が壊れている | 他のどの結論より先にこれを潰す |
| td だけ高く conv がほぼ 0 | 窓の分割が主因で td 固有 | 時間分割のコストとして受け入れるか、窓割り当てを変える |
| td も conv も同程度 | 両モード共通。csma 除外が主因 | 分母の定義を直す。モードの選択とは無関係 |

td と conv の両方を出すのは、分子と分母のフレーム集合の関係が両者で違うため
（conv は同一窓・同一集合、td は互いに素）。詳細は `docs/per_measurement.md` §3–§5。

---

## 3. 均等性をどう判定するか

「集中しているか均等か」を目視の表だけで決めると、`cv` ブランチで避けようとしている
「分散の大きさを閾値と比べる」のと同じ恣意性が入る。そこで数値で出す。

Seed × {生 PER が負, 負でない} の 100 × 2 分割表に χ² 独立性検定
（`scipy.stats.chi2_contingency`）をかけ、χ²・自由度・p 値・Cramér's V を出す。

**判断に使うのは p 値ではなく効果量と実寸のばらつきである。** 観測数が 10⁶ オーダー
あるので、Seed 間にごくわずかな差があるだけで p は 0 に張り付く。p が有意であること
自体は何も意味しない。見るのは

- **Cramér's V**: 2 × k 分割表なので `V = sqrt(χ²/N)`、値域 `[0, 1]`。
  Seed と「負になるか」の連関の強さそのもの。`V < 0.05` なら実質的に無関連。
- **Seed 別クリップ率の最大 / 最小比**と**標準偏差 / 平均**: 「Seed 0 は 9.3%、
  Seed 42 は 9.7%」なのか「Seed 42 だけ 40%」なのかという実寸。こちらのほうが
  意思決定に直結する。

二項分布の素のゆらぎで説明できる範囲かどうかの目安も併記する。Seed あたりの観測数を
`n`、全体率を `p̄` とすると、率の標準偏差の期待値は `sqrt(p̄(1−p̄)/n)` なので、
**実測の標準偏差がこれと同程度なら「均等」、数倍大きければ「Seed 依存の上乗せが
ある」**と読める。

## 4. 出力

```sh
python3 script/check_per_range.py                 # td と conv の両方
python3 script/check_per_range.py --mode conv     # 片方だけ
python3 script/check_per_range.py --csv <path> --out <path>
```

`plots/simulation_results.csv` を 1 回読むだけ。再解析も再シミュレーションも不要。

標準出力:

1. モードごとの Seed 別表 ―― `n_obs`, `PER<0` 件数と率, `PER>1` 件数, `n_invalid`,
   `n_zero_denom`, 生 PER の最小・最大
2. Seed 間ばらつきのまとめ ―― 率の平均・標準偏差・最小・最大・最大/最小比、および
   二項ゆらぎから期待される標準偏差との比
3. χ² 均等性検定と Cramér's V
4. 読み方のガイド

明細は `plots/per_range_by_seed.csv` に出る。列は
`mode, seed, n_obs, n_neg, neg_rate, n_gt1, n_invalid, n_zero_denom, min_per, max_per`。

### 読み方

| 出力 | 読み |
|---|---|
| `PER>1` が全モードで 0 件 | 定義どおり。列ずれも無し |
| `PER>1` または `n_invalid` が 1 件でもある | CSV が壊れている。最優先で調査 |
| Cramér's V < 0.05 かつ 最大/最小比 ≈ 1 | 全 Seed 均等。構造的要因。Seed 除外は無効 |
| 実測の率の標準偏差 ≈ 二項ゆらぎの期待値 | 同上。Seed 依存の上乗せは無い |
| 一部 Seed だけ率が突出 | その Seed の除外を検討 |
| `n_zero_denom` が大きい | PER = 0 に化けている観測が多い。統計量が過小評価される |

## 5. 実行場所

`plots/simulation_results.csv` は `.gitignore` 対象で、開発機（ローカル）には無い。
計算機側で

```sh
git fetch && git checkout per_range_check
python3 script/check_per_range.py
```

ローカルでは、`create_csv.py --header-only` で生成したヘッダに既知の値を仕込んだ
合成 CSV でスモークテストのみ行っている（列名のタイプミスと分類ロジックの検証）。

`analyze_csv.py` / `create_csv.py` / `diagnose_per_clip.py` には変更を入れていない。
driot にも base_simulator にも変更は不要。
