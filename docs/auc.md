# AUC と ROC 曲線

干渉検知の性能を、閾値の選び方に依らない形で測る。実装は

- `script/analyze_csv.py::_rank_auc()` ―― AUC の計算
- `script/plot_roc.py` ―― ROC 曲線の作図

全体の構成は `docs/README.md` を参照。ここは AUC/ROC に絞った詳細。

---

## 1. なぜ F1 と AUC の両方を出すのか

F1 は**閾値 τ を 1 点に決めたときの性能**である。`evaluate_interference_detection()`
は `VARIANCE_THRESHOLDS`（0.000〜1.000 を 0.001 刻み、1001 通り）を全部試し、
F1 が最大になる τ を選んで `best_threshold` 列に記録する。

これには 2 つの性質がある。

1. **選んだ τ は運用で使える値ではない。** 干渉の有無を知った上で最適化しているので、
   F1 は楽観側に偏った上限になる。
2. **グリッドの刻みに依存する。** 実データの `best_threshold` は 0〜0.143 に
   収まっており、0.001 刻みでは候補が実質 143 通りしかない。

AUC は τ を決めずに、**スコアの分離度そのもの**を測る。両方を並べると

| 観測 | 読み |
|---|---|
| AUC が高いのに F1 が低い | 分離はできている。閾値の取り方に問題がある |
| AUC も低い | 統計量が干渉を捉えられていない |

という切り分けができる。

## 2. 入力になるスコア

AUC は 2 クラスの分離度なので、まず「干渉あり」「干渉なし」の 2 群のスコアを作る。

ある条件（帯域ペア, 距離, 両PANの負荷, どちらの PAN から見るか）について、
Seed ごとに次を計算する（`compute_seed_max_variance()`）。

1. デバイスごとに `ΔPER = PER_DL − PER_UL`
2. RSSI でビン分け（起点 = 受信感度 + 3 dBm、幅 10 dBm）
3. ビンごとに ΔPER の分散を取り、**その Seed 内での最大値**を干渉指標とする

これを Seed 100 本ぶん繰り返すと、長さ 100 の配列が 2 本できる。

| 変数 | 中身 | ラベル |
|---|---|---|
| `interf_values` | 同一周波数ペア（ch 0–2 どうし）の 100 Seed | 陽性 |
| `no_interf_values` | 別周波数ペア（ch 0–2 vs 3–5）の 100 Seed | 陰性 |

対になるのは**同じ帯域・同じ負荷で、干渉の有無だけが違う**条件同士。
対応づけは `run_interference_detection()` が `get_interf_label()`
（2つのチャネルの周波数が一致すれば `interf`）で行う。

**F1 と AUC はこの同じ 2 本の配列を共有する。** 統計量を変えているわけではなく、
同じスコアに対する 2 通りの要約である。

スコアそのものは `plots/detection_scores{,_conv}.csv` に残してある
（300 セル × 200 Seed = 60,000 行）。検知結果 CSV は最良閾値 1 点の混同行列しか
持たないので、そこからは ROC を復元できないため。これを残しておけば 155MB の
`simulation_results.csv` を再解析せずに曲線を引き直せる。

## 3. AUC の定義と実装

```
AUC = P(指標_interf > 指標_no_interf) + 0.5 × P(同値)
```

陽性と陰性から 1 つずつ無作為に取り出したとき、陽性のほうが大きい確率。
同値は 0.5 と数える。ROC 曲線の下側面積と数学的に一致する（Mann–Whitney U と等価）。

- 1.0 = 完全に分離
- 0.5 = ランダムと同じ
- 0.0 = 完全に逆転

```python
def _rank_auc(interf_values, no_interf_values):
    n_pos = len(interf_values)
    n_neg = len(no_interf_values)
    if n_pos == 0 or n_neg == 0:
        return float("nan")

    ranks = stats.rankdata(np.concatenate([interf_values, no_interf_values]))
    return (ranks[:n_pos].sum() - n_pos * (n_pos + 1) / 2.0) / (n_pos * n_neg)
```

3 段階になっている。

**(a) 2 群を連結して通し順位を振る。** 陽性を前半に置くので `ranks[:n_pos]` が
陽性側の順位になる。

**(b) 陽性側の順位和から最小値を引く。** 陽性が全部最下位なら順位は 1…n_pos で
和は `n_pos(n_pos+1)/2`。これを引いた残りが **U 統計量**で、「陽性が最低ラインから
どれだけ上に押し上がっているか」を表す。

**(c) 最大値 `n_pos × n_neg` で割る。** 陽性が全部陰性より上のときの U がこれ。

### 手計算の例

陽性 `[0.05, 0.02, 0.09, 0.02]`、陰性 `[0.01, 0.02, 0.03]`:

```
値    0.05  0.02  0.09  0.02 | 0.01  0.02  0.03
順位  6.0   3.0   7.0   3.0  | 1.0   3.0   5.0     ← 0.02 が3つ → midrank 3.0

陽性の順位和 R = 6.0 + 3.0 + 7.0 + 3.0 = 19.0
U   = 19.0 − 4×5/2 = 9.0
AUC = 9.0 / (4×3) = 0.75
```

12 通りの総当たりで「勝ち + 0.5×引き分け」を数えても 9.0/12 = 0.75 で一致する。

### なぜ閾値グリッド上の台形則にしないのか

`VARIANCE_THRESHOLDS` の刻み 0.001 が、指標の実測レンジに対して粗いため。
`best_threshold` は 0〜0.143 にしか分布しておらず、候補が実質 143 通りしかない。
順位ベースなら刻み幅にもグリッドの定義にも依存せず、値をそのまま使う。

> **訂正**: 以前この理由を「グリッドが 1.0 で打ち切られているので、指標が 1.0 を
> 超える条件では ROC が切れて AUC が頭打ちになる」と説明していたが、これは誤り。
> 指標は `ΔPER ∈ [-1, 1]` の分散なので**理論上限が 1.0** であり、グリッドの上端が
> 効く場面は存在しない。理由は上限ではなく刻みの粗さである。

### 向きを補正していない

判定は `evaluate_interference_detection()` の `v >= th` で片側固定、つまり
「分散が大きいほど干渉あり」という向きが決め打ちなので、AUC の向きも一意に決まる。

`max(auc, 1 − auc)` のような補正はしない。**0.5 を下回ったら「指標が干渉の有無と
逆相関している」という情報そのもの**で、補正するとそれが潰れるため。

（`cv` ブランチの `analyze_cv.py` は `rule` が `ge`/`le` の両向きを取るので、
そちらに AUC を入れるなら向きの扱いを別途決める必要がある。だから入れていない。）

### 同値の扱い

`rankdata` は同順位に **midrank**（平均順位）を与えるので、同値ペアが自動的に
0.5 として数えられ、定義式の `+ 0.5 × P(同値)` が再現される。

同値が出る経路は実在する。有効ビン（端末 2 個以上）が 1 つも作れなかった Seed は
`compute_seed_max_variance()` が `max_var` の初期値 0.0 をそのまま返すため。
実データでは退化 Seed は td/conv とも 0 件だった（CSV の `n_degenerate_*` 列）。

### 端のケースと丸め

- どちらかの群が空なら `nan`。実データでは常に 100 Seed ずつなので起きない。
- CSV には**小数 4 桁**で書く。100×100 = 10,000 ペアなので刻みが 1e-4 であり、
  それ以上の桁に意味が無い。他の指標が 3 桁なのに 1 桁多いのはこのため。

### 依存

`scipy.stats` は元から import 済みなので新しい依存は無い。sklearn は実装には
使わず、検証でのみ使う。

## 4. AUC ヒートマップ

`create_heatmap.py --metric auc` で、PAN1負荷 × PAN2負荷の 5×5 格子に AUC を
色で出す（`plots/heatmaps_auc{,_conv}/`、12枚ずつ）。1枚が (帯域ペア, PAN) の1組。

色の範囲は F1 版と同じ **0.5–1.0** に揃えてあるので、2つを並べて
「同じ濃さ＝同じ値」として読める。

**セルには `AUC=x.xxx` だけを出し、閾値は出さない。** AUC は閾値の選び方に
依らない指標で、τ という概念自体が無いため（F1 版は `Tau:` を併記している）。
桁数を 3 にしているのは刻みが 1e-4 だから。

この図の軸は `pan1_offload` / `pan2_offload` そのもので、**自分 / 相手への
読み替えはしていない**（`PAN2` の図では縦が相手、横が自分になる）。
読み替えた断面が見たいときは折れ線グラフか ROC のほう。

## 5. ROC 曲線

τ を高い方から下げていったときの `(FPR(τ), TPR(τ))` の軌跡。

```
TPR(τ) = #{干渉あり Seed で 指標 ≥ τ} / 100     ← 再現率
FPR(τ) = #{干渉なし Seed で 指標 ≥ τ} / 100     ← 誤検知率
```

### τ の動かし方

**F1 の固定グリッドは使わない。** 観測されたスコアの値そのものを閾値にする。
τ を連続的に動かしてもスコアの値をまたぐ瞬間にしか TP/FP は変わらないので、
相異なるスコアの数だけ点を打てば過不足がない。1 本の曲線は最大 201 点
（陽性100 + 陰性100 + 始点）。

| | 範囲 | 刻み |
|---|---|---|
| F1 の τ | 0.000 〜 1.000（固定） | 0.001（1001 通り） |
| ROC の τ | +∞ 〜 観測された最小スコア | 観測値そのもの |

始点 `(0,0)` は τ = +∞（誰も陽性と判定しない）、終点 `(1,1)` は最小スコア以下
（全員を陽性と判定）。

### 同値は 1 点にまとめる

```python
idx = np.r_[np.where(np.diff(scores))[0], len(scores) - 1]
```

同じスコアが陽性側と陰性側の両方にあると、**その τ を境に TP と FP が同時に増える**。
1 件ずつ点を分けると「先に TP だけ増えてから FP が増えた」ように見え、階段が実際より
良く描けてしまう。まとめると曲線はそこで斜めに進む。

### ROC 図の構成

断面は折れ線グラフと揃えてあり、**相手PAN負荷 = 100% に固定**。

```
plots/roc/roc_own{50,100,200}_{conv,td}.pdf   = 6枚

 +------------+------------+------------+
 | 相手50kbps | 相手100kbps| 相手200kbps|
 |  TPR       |            |            |
 |   | 5本    |            |            |
 |   +-- FPR  |            |            |
 +------------+------------+------------+
   凡例: 自PAN負荷 20/40/60/80/100% (AUC 0.xxx)
```

1 パネル内に自PAN負荷 5 段ぶんの曲線が重なる。配色は 2 度やり直している。

| 試行 | 方針 | 全ペア最小 ΔE（通常視） | 問題 |
|---|---|---:|---|
| 1 | 単一色相 blue の濃淡 | 5.0 | 5 段を濃淡だけでは分けられない |
| 2 | 寒色→暖色の 5 色相 | 7.1 | 赤とオレンジ、青と紫と緑が紛らわしい |
| 3（現行） | Okabe-Ito から 5 色 | **16.4** | ― |

**順序感より識別しやすさを優先した。** Okabe-Ito（色覚多様性を考慮した定番の
定性配色）から、白地でコントラスト 3:1 以上の 5 色を採っている。

| 負荷 | 色 | 白地コントラスト |
|---|---|---:|
| 20% | `#0072B2` blue | 5.2:1 |
| 40% | `#009E73` green | 3.4:1 |
| 60% | `#D55E00` vermillion | 3.9:1 |
| 80% | `#CC79A7` purple | 3.1:1 |
| 100% | `#000000` black | 21.0:1 |

全ペアの OKLab ΔE は最小 16.4（orange–purple）で、床の 15 を超える。
明度も 3.1:1〜21:1 と大きくばらけているので、白黒印刷でも色相だけに頼らない。
線幅は 2.0 → 2.8 に太くした。細いと色が判別しにくいため。

**マーカーは使わない。** 冗長符号化として一度入れたが、階段状の曲線に点が乗ると
逆に読みにくくなった。

負荷の順序は、凡例が昇順に AUC 付きで並ぶことと、曲線が入れ子状に並ぶ位置で読む。

自分 / 相手の読み替え規則は `plot_detection_lines.py::own_other()` が唯一の定義元で、
`plot_roc.py` はそれを import する。

| 検証項目 | 結果 |
|---|---|
| `_rank_auc` vs `sklearn.roc_auc_score` | 600 セル全て一致（最大誤差 2.2e-16） |
| `_rank_auc` vs ROC 曲線の台形則面積 | 600 セル全て一致（最大誤差 2.2e-16） |

| `roc_curve` vs `sklearn.roc_curve`(drop_intermediate=False) | 600 セルで曲線・点数とも完全一致 |
| ROC の始点 `(0,0)` / 終点 `(1,1)` | 600 セル全て成立 |
| FPR/TPR の単調性・値域 `[0,1]` | 600 セル全て成立 |
| `own_other()` のキー一意性 | 45 キー、衝突 0（スコアが混ざる事故が無い） |
| ROC 図の凡例 AUC vs CSV の `auc` 列 | 90 本全て一致 |
| 折れ線 `--metric auc` の描画値 vs CSV | 90 点全て一致 |
| スコアCSVの構造 | 300 セル × (100, 100)、seed 重複 0 |

単体では境界ケース（完全分離・完全逆転・全同値・同値多数・片側1要素）と
同値を多く含むランダム 200〜300 ケースでも sklearn と一致を確認している。

**つまり図に描いてある曲線の面積が、CSV の `auc` 列そのものである。**

## 7. 実データの読み方

### 全体

| | AUC 中央値 | F1 中央値 |
|---|---|---|
| conv | **0.966** | 0.912 |
| td | **0.824** | 0.769 |

conv が明確に上。時間分割（td）のコストがここに出ている。

### 自PAN負荷が上がると落ちる

自PAN負荷別の AUC 中央値:

| 自PAN負荷 | conv | td |
|---:|---:|---:|
| 20% | 0.998 | 0.897 |
| 40% | 0.996 | 0.900 |
| 60% | 0.990 | 0.860 |
| 80% | 0.931 | 0.799 |
| 100% | 0.887 | 0.751 |

自分のトラフィックが増えるほど、自PAN内の輻輳由来のばらつきが相手の干渉の
痕跡を覆い隠す。

### AUC < 0.5 のセル

td で 6/300、conv で 1/300。**7 件すべてで相手PAN負荷が 20%** だった。

```
自100kbps 相200kbps  自負荷100% 相負荷 20%  AUC 0.4705   (td)
自200kbps 相100kbps  自負荷100% 相負荷 20%  AUC 0.4775   (td)
自100kbps 相 50kbps  自負荷 60% 相負荷 20%  AUC 0.4797   (td)
...
自100kbps 相 50kbps  自負荷100% 相負荷 20%  AUC 0.4762   (conv)
```

相手がほとんど送信していないので**検知すべき干渉が実質存在せず**、2 群が区別
できない。AUC は 0.5 近傍に張り付き、ノイズで下側に振れたものが 0.5 を割る。
異常ではなく、そういう条件だというだけ。これらのセルは F1 も 0.667 前後、
つまり「全部を干渉ありと判定した」退化状態になっている。

**ROC 図にはこれらは出ない。** 図は相手負荷 100% の断面に固定しているため。

```sh
python3 script/plot_roc.py            # 図だけ引き直す (スコアCSVがあれば手元でも可)
python3 script/plot_roc.py --format png --out-dir /tmp/roc
```

`plot_roc.py` は現在 `(fpr, tpr)` しか返しておらず、**各点の τ は出していない**。
