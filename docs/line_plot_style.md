# 折れ線グラフの体裁変更

折れ線グラフ (`script/plot_detection_lines.py`) の見た目だけを変える。
AUC の値・断面・系列の選び方は一切変えない。

## 1. 何を変えるか

| 項目 | 変更前 | 変更後 |
|---|---|---|
| ΔPER only の線種 | 破線 `--` | 長い破線 `(0, (8, 4))` |
| RSSI only の線種 | 点線 `:` | 丸い点の列 `(0, (0.1, 3.0))` + 丸キャップ |
| 点 (マーカー) | 塗りつぶし | **白抜き** (面は白、縁は線の色) |
| 3手法を重ねた図の凡例 | 色 3項目 + 線種 3項目 (計6) | **3×3 の行列** (行 = 手法、列 = 相手帯域) |
| 点と髭の横位置 | 系列ごとに 1.2% ずつずらす | **ずらさない** (本来の負荷の位置) |
| グリッド線 | 縦・横 | **横線だけ** (折れ線の全図。ROC 曲線は縦横のまま) |

### 線種

変更前の `--` と `:` は、線幅 2.0 だと破線の間隔が近く、印刷・縮小すると区別しにくい。
片方を「長い破線」、もう片方を「丸い点の列」にして、線の形そのものが違うようにする。

- ΔPER only: 線分 8 pt・間隔 4 pt の長い破線
- RSSI only: 長さほぼ 0 の線分を丸キャップで描き、直径 = 線幅の点を 3 pt 間隔で並べる

提案手法は実線のまま。

### 白抜きの点

マーカーの面を白 (`markerfacecolor="white"`)、縁を線の色にする。縁の太さは 1.8。
白抜きにすると縁だけで形 (○□△) を読むことになるので、大きさを 6 → 8 に上げる。
髭 (信頼区間) の上に点が来るよう、線と点は髭より手前に描く。

モード比較図 (`--mode compare`) も同じ `_draw_series()` を通るので白抜きになる。

### 3×3 の行列凡例

変更前の凡例は「色 (帯域) 3項目 + 線種 (手法) 3項目」で、6本の線があるように見えた。
実際の線は 3手法 × 3帯域 = 9 本なので、9 本をそのまま行列で並べる。

```
              (列1)        (列2)         (列3)
Proposed      ─○─ 50 kbps  ─□─ 100 kbps  ─△─ 200 kbps
ΔPER only     ‐○‐ 50 kbps  ‐□‐ 100 kbps  ‐△‐ 200 kbps
RSSI only     ·○· 50 kbps  ·□· 100 kbps  ·△· 200 kbps
```

- 1列目は手法名だけ (線の見本なし) の行見出し
- 各セルの見本は、図中の線と同じ 色・線種・白抜きマーカー
- matplotlib の凡例は列方向に詰めるので、`ncol=4` で
  [見出し3つ] → [50 kbps の3手法] → [100 kbps の3手法] → [200 kbps の3手法] の順に渡す
- 凡例が大きくなり、軸の中に置くと線に重なるので、**軸の上側の外**に置く
  (単独図・3パネル図とも)

手法が1つだけの図 (`*_proposed` / `*_dper` / `*_rssi`) は、線種の軸が無いので
帯域3項目の凡例のまま。ただし、変更前は凡例の見本が常に実線で、
dper / rssi の図では図中の線種と食い違っていたので、見本の線種を図中に揃える。

### 横へのずらし (dodge) をやめる

髭があるとき、`icc` は同じ負荷の点と髭が真上に重ならないよう、系列ごとに横へ
1.2% ずつ (9本なら ±4.8%) ずらしていた。重なりは減るが、点が本来の負荷
(20, 40, ... %) の位置から外れて見える。そこで `CI_DODGE = 0.0` にして、
すべての点と髭を本来の負荷の位置に描く。

代わりに、同じ負荷で値の近い系列は点と髭が重なる。点は白抜きで髭より手前に
描くので、点の形 (○□△) と縁の色は読める。重なりが読みにくければ
`CI_DODGE` を 1.2 に戻すだけで元の描き方になる。

### 3×3 グリッド図 (`auc_grid.pdf`)

3手法を重ねた図 (`auc_*_compare.pdf`) は、1パネルに 3手法 × 3相手帯域 = 9 本の線が乗り、
ずらしを止めたことで点と髭も重なって読みにくい。そこで、帯域の組を**位置**で分けた
3×3 の小さな図 (small multiples) を足す。

```
              Other 50 kbps   Other 100 kbps   Other 200 kbps
Own 50 kbps    [P  D  R]        [P  D  R]         [P  D  R]
Own 100 kbps   [P  D  R]        [P  D  R]         [P  D  R]
Own 200 kbps   [P  D  R]        [P  D  R]         [P  D  R]
```

- 行 = 自帯域、列 = 相手帯域。1パネルの線は 3手法の 3本だけ
- 帯域は位置で読めるので、**色を手法に割り当てる** (Proposed 橙 / ΔPER only 青 / RSSI only 緑)。
  線が重なったときに提案手法が隠れないよう、**提案手法を最後に描いて一番手前に出す**
  (3手法を重ねた `*_compare` 図も同じ描画順)。
  線は**全部実線**にし (1パネル3本なので線種で分ける必要が無い)、マーカー (○ / □ / △) を
  手法ごとに変えて色に頼らず読めるようにする
- 横軸・縦軸は全パネル共通 (`choose_ylim()` の値)。軸ラベルも行見出し・列見出しも入れない
  (並び順は上の表のとおりで、図のキャプションで説明する)
- 凡例は手法の 3 項目を図の上に 1 行
- 点・髭の体裁 (白抜き、ずらし無し) は他の図と同じ `_draw_series()` を使う
- 出力: `plots/detection_lines/auc_grid.pdf` (single-query)、
  `plots/detection_lines_sequential/auc_grid.pdf` (multi-query)。モード比較には作らない

既存の 16 枚はそのまま残す。

### 信頼区間の髭が枠外に切れる問題を直す

y 軸の下端 (`choose_ylim()`) を AUC の点だけで決めていたので、点は枠内でも
髭の下端 (ブートストラップ 95% 区間の下限) が枠の外に出て切れていた
(例: single-query の ΔPER only、自帯域 200・相手 50 kbps・自負荷 100% は
点 0.47 / 下限 0.39 で、軸 0.4 から下が切れた)。
髭を描くときは、**区間の下限も含めた最小値**から下端を決める。0.1 刻みで切り下げ、
全図共通にする規則は変えない。

### 凡例の文字を大きくする

`LEGEND_FONTSIZE` を 18 → 22 にする (折れ線の全図)。

### モード比較図 (`detection_lines_mode_compare/`) を 3×3 グリッドにする

以前のモード比較図は、1パネルに 3相手帯域 × 2モード = 6本の線が乗り、色 (帯域)・
線種 (モード)・マーカー (帯域) を同時に読み分ける必要があって見にくかった
(配色を紫の濃淡 → 金 / マゼンタ / 黒 → 赤 / 紫 / 紺 → 赤 / 紫 / 山吹 と変えても解消しなかった)。
3手法のグリッド図 (`auc_grid.pdf`) と同じく、帯域の組を位置で分ける。

```
 (手法ごとに1枚)   Other 50    Other 100   Other 200
 Own 50           [S  M]       [S  M]       [S  M]
 Own 100          [S  M]       [S  M]       [S  M]
 Own 200          [S  M]       [S  M]       [S  M]
```

- **手法ごとに1枚** (計3枚): `auc_grid_proposed.pdf` / `auc_grid_dper.pdf` / `auc_grid_rssi.pdf`
- 行 = 自帯域、列 = 相手帯域 (`auc_grid.pdf` と同じ並び)。行・列の見出しは入れない
- **1パネルは single-query と multi-query の2本だけ**。同じ条件の2本が隣り合うので、
  時間分割 (multi-query) でどれだけ落ちるかがそのまま読める
- 色 = モード: **single-query 赤、multi-query 紫**。線は両方実線、マーカーは ○ / □
- 両モードの 95% 信頼区間の髭、白抜きの点、y 軸の決め方は他の図と同じ
- 凡例はモードの2項目を図の上に1行

自帯域ごとの単独図3枚 + 3パネル図1枚 (手法ごと4枚、計12枚) は、この3枚に置き換える。

### AUC = 1.0 の線が切れないようにする

y 軸の上端をちょうど 1.0 にしていたので、AUC = 1.0 の線と点の上半分が枠で切れていた。
描画範囲の上端を 1.0 + 0.03 に広げ (`YTOP_PAD`)、目盛りは 0.1 刻みで 1.0 までに固定する
(折れ線の全図)。

### 相手 PAN の負荷ごとに描き、ファイル名を見分けやすくする

以前は相手 PAN の負荷を 100% に固定した断面だけを描いていた。これを
**相手負荷 20 / 40 / 60 / 80 / 100% の5通りすべて**について描く (折れ線の全図)。
断面の選び方 (own/other の読み替え、対称ペアは PAN1 側) は `own_other()` のまま、
相手負荷だけを引数にした。y 軸は5つの相手負荷すべてで共通 (`choose_ylim()` に全部渡す)。

ファイル名は、図を `plots/` の外に持ち出しても何の図か分かるよう、
**測定モード・図の種類・相手負荷**を必ず入れる:

```
auc_<モード>_<中身>_<形>_otherload<相手負荷3桁>.pdf
```

| 部品 | 値 |
|---|---|
| モード | `single` (single-query) / `multi` (multi-query) / `modecompare` (両モードの比較) |
| 中身 | `proposed` / `dper` / `rssi` (手法1つ) / `3methods` (3手法) |
| 形 | `own50kbps` / `own100kbps` / `own200kbps` (自帯域ごとの単独図) / `3panel` / `grid` (3×3) / `gridtable` (3×3 + 各パネルの数値表) |
| 相手負荷 | `otherload020` / `otherload040` / `otherload060` / `otherload080` / `otherload100` (3桁にそろえて名前順 = 負荷順にする) |

例:

| ファイル | 中身 |
|---|---|
| `detection_lines/auc_single_3methods_grid_otherload100.pdf` | single-query、3手法の 3×3 グリッド、相手負荷 100% (旧 `auc_grid.pdf`) |
| `detection_lines_sequential/auc_multi_dper_3panel_otherload060.pdf` | multi-query、ΔPER only の3パネル、相手負荷 60% |
| `detection_lines_mode_compare/auc_modecompare_proposed_grid_otherload020.pdf` | 提案手法の single / multi 比較、相手負荷 20% (旧 `auc_grid_proposed.pdf`) |

旧名 → 新名: `auc_own{bw}_{手法}` → `auc_<モード>_{手法}_own{bw}kbps_otherload<L>`、
`auc_own{bw}_compare` → `auc_<モード>_3methods_own{bw}kbps_otherload<L>`、
`auc_3panel_{手法|compare}` → `auc_<モード>_{手法|3methods}_3panel_otherload<L>`。

**帯域には `kbps` を付け、相手負荷は `otherload` と書く。** 最初は相手負荷を `other100` と
書いていたが、ROC 曲線のファイル名では `other200` が相手の**帯域**を表していて、同じ
`other` が図によって負荷と帯域の両方の意味になっていた。帯域 = `<own|other><数値>kbps`、
相手負荷 = `otherload<3桁>` に統一して見分けられるようにした。

枚数: single-query / multi-query それぞれ (16 + グリッド1) × 5 = 85 枚、
モード比較は 3手法 × 5 = 15 枚。描画値の CSV は `auc_<モード>_plotted_values.csv` に
5つの相手負荷ぶんをまとめる (`other_load_percent` 列で区別)。
スコア分布のヒストグラムは従来どおり相手負荷 100% の断面のまま。

### ROC 曲線も相手負荷ごとに描く

`plot_roc.py` も相手負荷 20 / 40 / 60 / 80 / 100% の5通りすべてで描く。1枚 = (自帯域, 相手帯域,
手法, 相手負荷)、線は自負荷 5本 (凡例に AUC) で、中身は従来と同じ。1モード 27 × 5 = 135 枚。
名前は折れ線と同じ規則にそろえる:

```
roc_<single|multi>_<手法>_own<自帯域>kbps_other<相手帯域>kbps_otherload<相手負荷3桁>.pdf
例: roc/simultaneous/roc_single_proposed_own100kbps_other50kbps_otherload100.pdf
   (旧 roc_own100_other50_proposed.pdf)
```

### 3×3 グリッド図の各パネルの下に AUC の数値表を付けた版を足す

3×3 グリッド図 (`grid`) は、9 通りの帯域ペアの判定結果を並べているが、点の値は図から
読み取るしかなかった。論文・発表で数値も示せるよう、**各パネルの直下に、そのパネルの
AUC の数値表を付けた版**を新しく足す。**既存の `grid` 図はそのまま残し、別ファイルにする。**

- 形の名前は `gridtable`。例:
  `detection_lines/auc_single_3methods_gridtable_otherload080.pdf`、
  `detection_lines_sequential/auc_multi_3methods_gridtable_otherload080.pdf`、
  `detection_lines_mode_compare/auc_modecompare_proposed_gridtable_otherload080.pdf`
- 対象は `grid` を描いている図すべて (3手法グリッド: single / multi、モード比較グリッド: 3手法)。
  相手負荷 5 通りすべて
- 表の列 = 自PAN負荷 20 / 40 / 60 / 80 / 100%。列の中心がパネルの横軸の点の位置にそろうように置く
- 表の行 = そのパネルの線 (3手法グリッドは Proposed / ΔPER only / RSSI only、
  モード比較は single-query / multi-query)。行見出しは凡例と同じ色で書く
- セルは **AUC の点推定** (全 Seed から出した値、小数3桁)。ブートストラップ平均ではない。
  信頼区間は図の髭と `auc_*_plotted_values.csv` / `docs/auc_otherload080_summary.md` で読む
- パネル・線・髭・凡例・y 軸範囲は `grid` と同じ (`_plot_bw_grid()` を共有し、表の有無だけを引数で切り替える)

枚数: single / multi それぞれ +5 枚、モード比較 +15 枚。

### 凡例・目盛りを大きくし、縦軸を 0.2 刻みにする (ヒートマップ・ROC も)

論文に載せたとき読みにくいという指摘を受けて、文字を一段大きくする。値・断面は変えない。

| 項目 | 変更前 | 変更後 | 効く図 |
|---|---|---|---|
| 凡例の文字 (`LEGEND_FONTSIZE`) | 22 | **28** | 折れ線の全図 (ROC の凡例はこの −2) |
| 目盛りの数字 (`TICK_LABELSIZE`) | 20 | **26** | 折れ線の全図・ROC (`style_axes()` 経由) |
| 折れ線の縦軸の目盛り | 0.1 刻み | **0.2 刻み** (`YTICK_STEP`) | 折れ線の全図 |
| ヒートマップのセル内の AUC | 19pt、`0.789` | **30pt、`.789`** (先頭の 0 を省く。`1.000` はそのまま) | ヒートマップ |
| ヒートマップの軸・カラーバーの目盛り | 20 | **34** (`HEATMAP_TICK_LABELSIZE` / `CBAR_TICK_LABELSIZE`) | ヒートマップ |

縦軸の目盛りは「下端から 0.2 ずつ」ではなく「**0.2 の倍数のうち描画範囲に入るもの**」にする。
下端が 0.5 のとき下端から数えると 0.5/0.7/0.9 になり、1.0 に目盛りが乗らないため
(下端 0.2 なら 0.2/0.4/…/1.0、下端 0.5 なら 0.6/0.8/1.0)。描画範囲 (`choose_ylim()`) 自体は変えない。

ヒートマップのセルの数値は小数3桁で丸めてから先頭の `0` だけを落とす。丸めて `1.000` になる値はそのまま出す。
文字を大きくすると `1.000` が隣のセルに届いたので、セルを 1.70 → **2.10 インチ** (`CELL_SIZE`) に広げた。
さらに文字を上げたとき (セル 25 → 30pt、目盛り 28 → 34pt) は、**セルはそれ以上広げず**、カラーバーを既定
(軸の幅の 15%) から **5%** に細くしてセルの幅を確保した。論文では図ごと列幅に縮小されるので、セルを文字と
同じ比で広げると紙面上の文字の大きさは変わらない (25pt / 2.1 インチ と 30pt / 2.5 インチ はほぼ同じ見え方)。

ROC の凡例は `LEGEND_FONTSIZE` に連動させず **20pt のまま**にする (`ROC_LEGEND_FONTSIZE`)。
連動させると 26pt になり、6.6 インチ四方の図で凡例が曲線の半分を覆った。ROC の目盛りの数字は 26 に上がる。

## 2. 変えないもの

- AUC の値、own/other の読み替え (`own_other()`)

## 3. 実行

```sh
python3 script/plot_detection_lines.py                 # single-query
python3 script/plot_detection_lines.py --mode sequential
python3 script/plot_detection_lines.py --mode compare
```

計算機では `./script/plot_figures.sh` が上の3つを呼ぶ。
